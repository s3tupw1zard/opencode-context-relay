# Pocket ID OAuth setup

Use the existing Pocket ID as authorization server; this service is only a resource server. Its exact resource/audience is `MCP_PUBLIC_URL`, including `/mcp`. The Supabase infrastructure URL `https://supabase.s3tupw1zard.dev` is not the MCP endpoint or Pocket ID issuer. No Supabase service-role or anonymous key is needed.

1. Choose a separate MCP HTTPS domain. In Pocket ID **Settings → APIs**, add an API with resource identifier equal to the complete MCP URL, for example `https://context.s3tupw1zard.dev/mcp`, and permission `context.read`.
2. In **Settings → Application Configuration → OIDC**, allow the exact ChatGPT client metadata URL shown by the connection setup. CIMD is disabled until an allowlist is configured. Public metadata clients use `token_endpoint_auth_method=none`; use authorization-code PKCE S256. Restrict the allowlist and delegated API access to your intended account/groups and permission. In the API settings permit metadata-document clients with delegated access to `context.read`.
3. Current ChatGPT supports `https://chatgpt.com/oauth/client.json` with redirect `https://chatgpt.com/connector_platform_oauth_redirect` when authorization-response issuer identification (RFC 9207) is supported. Otherwise it may show a connection-specific metadata URL and callback. Use the actual displayed pair; do not guess callback IDs or add wildcard redirects. For a manually registered OIDC client, configure that exact callback, public client/PKCE and delegated API access; use connection setup's manual-client option where available.
4. Set `OAUTH_ISSUER` to Pocket ID's exact discovered issuer, and `OAUTH_ALLOWED_SUBJECT` to your user subject. `OAUTH_JWKS_URL` may be omitted: startup reads `/.well-known/openid-configuration`, requires HTTPS endpoints, exact issuer, S256, authorization_code and refresh_token grants. If supplied, JWKS must equal discovery. Old Pocket ID versions lacking API resources or CIMD must be upgraded/configured; discovery alone cannot verify API permission grants.
5. Restart and verify public `/.well-known/oauth-protected-resource/mcp`, then connect using the MCP HTTPS URL. Anonymous `/mcp` returns 401 with a metadata challenge; `/health` requires a valid token. Do not put a Caddy Basic Auth page in front of OAuth endpoints.

The client sends `resource=MCP_PUBLIC_URL` on authorization/token requests. Pocket ID issues an API access JWT, not an ID token. The consumer checks signature (RS256/ES256), `iss`, exact resource in `aud`, required unexpired `exp`, valid `nbf`, nonempty `sub`, optional configured subject restriction and `context.read` scope. Space-delimited and array scopes are supported. Missing/incorrect claims return 401 before database reads. Keys are cached/refreshed by jose.

Refresh token issuance, storage, rotation and renewal are handled by Pocket ID and ChatGPT's OAuth client; this server never stores refresh tokens or client secrets and does not implement a new authorization server. Ensure authorization-code and refresh-token grants are allowed in the metadata/manual client configuration. Do not invent an `offline_access` requirement; inspect the installed provider/client behavior.

`OAUTH_ALLOW_SHARED_BACKEND=true` is an explicit opt-in when omitting `OAUTH_ALLOWED_SUBJECT`: every user who has valid delegated resource permission can read the same backend. Default false requires the subject restriction. There is no per-user row isolation; keep this private single-owner setup restricted.

References: [Pocket ID APIs](https://pocket-id.org/docs/guides/apis), [Pocket ID CIMD](https://pocket-id.org/docs/guides/client-id-metadata-documents), [OpenAI plugin OAuth](https://developers.openai.com/plugins/build/auth).

If installed Pocket ID does not advertise CIMD, first enable its exact client metadata allowlist and check discovery again. If that version cannot support metadata clients, the minimal alternative is a manually registered public OIDC client with exact ChatGPT callback and S256, provided the ChatGPT connection offers manual client configuration. If resource/API audience or PKCE support is missing, upgrade Pocket ID; do not weaken token validation or substitute ID tokens.
